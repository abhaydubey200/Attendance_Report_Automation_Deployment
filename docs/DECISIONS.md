# Architectural Decision Log

| ID | Date | Decision | Rationale |
|---|---|---|---|
| D-001 | 2026-11-14 | Repository root is the project root (not a nested `APIS_INTELLIGENT_HR_MIS/` folder) | Avoids an extra level; the layout matches PRD section 6 otherwise |
| D-002 | 2026-11-14 | Added a `core/` package (settings, logging, paths, time) not listed in the PRD | `config/` holds YAML only; cross-cutting code needed a home that isn't UI or domain |
| D-003 | 2026-11-14 | SQLite `dev_sqlite` profile for development; SQL Server `mssql` profile for real use. SQLite is **rejected when APP_ENV=production** | No SQL Server is reachable from the laptop (PRD 10.1 allows a temporary dev DB behind abstractions) |
| D-004 | 2026-11-14 | Logical schemas (`security`, `audit`, ...) are real SQL Server schemas. On SQLite they are flattened with `schema_translate_map`, and table names are globally unique | One set of models and migrations for both backends |
| D-005 | 2026-11-14 | Alembic for migrations; `main.py init-db` runs them | PRD 10.4 controlled migrations; programmatic entry for tests |
| D-006 | 2026-11-14 | Local bcrypt authentication with lockout (5 failures → 15 min), generic error messages, every attempt audited | "Secure local authentication" option in PRD 18.1. `auth_provider` column reserved for SSO |
| D-007 | 2026-11-14 | RBAC seeded from `config/security.yaml` into `security.*` tables. The principal is **reloaded from the DB on every request** | Central store (PRD 3.6). Role changes and deactivation take effect immediately |
| D-008 | 2026-11-14 | Department scope = `ATTENDANCE_VIEW_ALL_DEPARTMENTS` permission OR explicit `user_department_access` rows. Employee-level data needs `ATTENDANCE_VIEW_EMPLOYEE` **and** scope | HOD isolation (PRD 3.3). Directors are aggregate-only by default (PRD 3.4) |
| D-009 | 2026-11-14 | `SYSTEM_ADMIN` holds no HR data permissions | PRD 3.5 |
| D-010 | 2026-11-14 | ~~Every Streamlit page re-checks its permission~~ superseded by D-018 | — |
| D-011 | 2026-11-14 | Contracts are frozen Pydantic models with `extra="forbid"`, timezone-aware timestamps required, `CONTRACT_VERSION = 0.1.0-provisional` | Explicit, versioned contracts (PRD 6.2). Field sets are confirmed in Phase 4 |
| D-012 | 2026-11-14 | Leave defaults to `UNKNOWN` approval status, and only `APPROVED` counts as approved | PRD 8.6: pending or unknown leave must never silently become approved |
| D-013 | 2026-11-14 | All HR policy values in `attendance_rules.yaml` are `null`. Health check and dashboard flag them as PROVISIONAL | PRD section 15: do not invent rules |
| D-014 | 2026-11-14 | The server binds to `127.0.0.1` by default (`api.host`) and returns generic error bodies | Dev laptop should not expose HR data on the network. Production sets the address explicitly |
| D-015 | 2026-11-14 | Storage is UTC (`DateTime(timezone=True)`). Display and business dates use Asia/Kolkata | Unambiguous timestamps. SQLite returns naive values, normalised by `ensure_utc` |
| D-016 | 2026-11-14 | **Re-platform: Streamlit replaced by FastAPI (REST API) + React/TypeScript (Vite)** | Requested by APIS: the product is an automation to be integrated into the in-house intranet. API-first lets the intranet call it directly or embed the UI. The Python core is unchanged |
| D-017 | 2026-11-14 | Session = signed JWT (HS256, `APP_SECRET_KEY`) in an httpOnly, SameSite=Strict cookie with sliding idle expiry. The principal is reloaded from the DB on every request | The token is never readable by JS (XSS-resistant). Revocation and role changes are immediate. The secret is required in production; dev uses an ephemeral key |
| D-018 | 2026-11-14 | Every route declares `require(Perm.X)`. The UI navigation comes from `/auth/me` (server page registry `api/navigation.py`) | Single enforcement point. The UI cannot grant itself pages |
| D-019 | 2026-11-14 | CSRF guard: unsafe `/api/*` methods require header `X-APIS-Request: 1` (in addition to SameSite=Strict) | A custom header cannot be sent cross-origin without a CORS preflight, which the allowlist refuses |
| D-020 | 2026-11-14 | One-origin deployment: the API serves `frontend/dist` with SPA fallback (path-traversal safe). Vite dev server proxies `/api` | No CORS in the default setup. Simple to run on one Windows server |
| D-021 | 2026-11-14 | Security headers: CSP with configurable `frame-ancestors`, nosniff, same-origin referrer, `no-store` on API responses. OpenAPI docs disabled in production | HR data must not be cached. Embedding only by allowlisted intranet origins |
| D-022 | 2026-11-14 | Frontend dependencies pinned exactly (React 19, React Router 7, Vite 8, TypeScript 7, Vitest 5). No UI component library | Reproducible builds. Small dependency surface for IT review |
| D-023 | 2026-11-14 | **No login page by default** (`auth.mode: none`): every request acts as a configured local operator whose permissions come from the central role store. Allowed only when bound to localhost; refused in production; `serve --host` cannot bypass it. `local` (password) mode retained; intranet sign-in planned | Requested by APIS: no login page. Guardrails keep HR data from being exposed on the network without authentication and preserve RBAC for when identity comes from the intranet |
| D-024 | 2026-11-14 | APIS India Limited visual identity: honey gold `#F5B800`, honey brown `#835415`, bronze `#9F7B49`, gold `#D7AD5F`, cream `#FFFBF6`, espresso navigation, Literata + Jost (OFL, bundled via @fontsource), honeycomb motif, typographic "apis" oval wordmark until official logo artwork is supplied (`VITE_BRAND_LOGO`) | Requested by APIS. Palette and fonts taken from apisindia.com. No third-party font/CDN requests (works on an isolated intranet, CSP-compatible) |
| D-025 | 2026-11-14 | Phases 2-12 built before sample files and HR rules exist (requested by APIS). Column schemas are defined in the app from real sample files; every HR-dependent value stays null and yields PROVISIONAL / UNRESOLVED | Lets the workflow be exercised now without inventing source columns or policy |
| D-026 | 2026-11-14 | Employee identities resolved at processing time from verified mappings, not stored on source rows | A mapping fixed later applies to the next run without re-uploading |
| D-027 | 2026-11-14 | A run's identity = hash of uploads, rules, authority, schema versions, adjustments and mapping state | Identical inputs never duplicate results; any change creates a traceable new version |
| D-028 | 2026-11-14 | Exception resolutions create adjustments applied on the next run; open exceptions of a replaced run become SUPERSEDED | Source values are never edited; history stays complete |
| D-029 | 2026-11-14 | Charts are small hand-written SVG components | No chart dependency; CSP-safe; works offline |
| D-030 | 2026-11-14 | Synthetic generator moved to `demo/`; `main.py demo` builds a separate database in `storage/demo` | Demonstrations never mix with real data |
